# Резервирование и восстановление миров

Аккаунты, сессии, герои, комнаты, события и состояние экспедиции находятся в одном файле SQLite и его активном WAL. Оператор сервера хранит копии в закрытом каталоге на постоянном носителе. Для восстановления после потери хоста нужна дополнительная защищённая копия на другом носителе. Частота копирования определяет, сколько последних ходов можно потерять. Для первого сервера предлагается копировать ежедневно и перед каждым обновлением.

## Создание

Укажите фактический `DATABASE_FILE` нужного экземпляра и новое имя в существующем каталоге резервов. Пример для Linux-хоста с Node 24 и заранее созданным приватным каталогом:

```sh
node scripts/toolchain/sqlite-snapshot.mjs /srv/ure/data/ure.sqlite /srv/ure/backups/before-release.sqlite
```

Сервер может продолжать работу. Команда открывает источник для чтения, вызывает SQLite Online Backup, закрывает журнал копии, проверяет структуру базы, внешние ключи и наличие основных таблиц URE. Новый файл становится видимым под итоговым именем только после проверки. Файловая система каталога назначения должна поддерживать жёсткие ссылки. Если это сетевое хранилище без такой поддержки, сначала создайте копию на локальном томе и перенесите готовый файл.

Успех обозначается кодом выхода 0. Существующая копия или соседний журнал SQLite под выбранным именем вызывают отказ. Обрыв процесса может оставить служебный каталог `.ure-snapshot-*`; завершённые копии остаются под выбранными именами. Доступ к резерву эквивалентен доступу к данным игроков. При переносе используйте защищённое хранилище и отдельные права доступа.

## Восстановление

1. Остановите **только нужный экземпляр игры** и его автоматический перезапуск. Сохраните прежний том целиком для отката, включая имеющиеся WAL и SHM.
2. Подготовьте новый постоянный том или пустой приватный каталог с правами сервисного пользователя. Восстановите файл командой ниже. При ошибке оставьте прежний том на месте.

   ```sh
   node scripts/toolchain/sqlite-snapshot.mjs /srv/ure/backups/before-release.sqlite /srv/ure/restore/ure.sqlite
   ```

3. В конфигурации одного экземпляра укажите восстановленный файл через `DATABASE_FILE` либо подключите новый том по прежнему адресу. Начните с версии игры, совместимой с версией схемы копии. Запустите сервер, проверьте готовность, вход тестового пользователя, загрузку сохранённого мира и последние ожидаемые события.
4. При неудаче остановите этот экземпляр и верните прежнюю версию приложения и прежний целый том. Откат к более старой копии откатит также сохранённые после неё смены пароля и отзывы сессий. При необходимости отзовите затронутые сеансы до открытия доступа игрокам.

Тест `node --test tests/sqlite-snapshot.test.ts` на временных базах проверяет работающего писателя с WAL, восстановление данных мира, повторное открытие схемы, защиту существующей копии и отказ при нарушении связей. Восстановление в облаке проверяется отдельно на томах выбранного провайдера.
