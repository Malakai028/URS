# Первый публичный сервер

Игре нужен один процесс Node 24 с постоянным диском, входящие HTTP/HTTPS и прокси с поддержкой WebSocket. Команда ниже предназначена для хоста с Docker Compose, DNS-именем, направленным на хост, и открытыми портами 80/443.

```sh
export PUBLIC_ORIGIN=https://game.example.org
export URE_RELEASE=$(git rev-parse --short HEAD)
docker compose -f compose.production.yaml config --quiet
docker compose -f compose.production.yaml up --build -d
curl --fail "$PUBLIC_ORIGIN/healthz"
```

Замените пример адреса своим доменом. Caddy обслуживает TLS, игра слушает loopback в сетевом пространстве Caddy. Именованный том `saves` содержит новую серверную БД, том `certificates` сохраняет состояние TLS. Путь локальной рабочей базы в конфигурации публикации отсутствует. Для первого релиза используйте пустой серверный том. Данные почты и внешнего рассказчика задаются только при подключении этих служб.

Перед обновлением сохраните проверенную копию за пределами тома сервера и запишите текущую ревизию. При откате используйте прежний образ с совместимой схемой либо восстановите копию на отдельный том. [Резервирование и восстановление](SQLITE_RECOVERY.md)

На новом хосте проверьте два отдельных аккаунта через домашний и мобильный интернет, приглашение в один мир, движение, сообщения, состояние существа и повторный вход после замены контейнера. Ответ готовности проверяет доступ к таблице миров. Публичный URL фиксируется после проверки TLS, WSS и сохранений.
